To make a product demo video with an AI coding agent, open Claude Code, Codex or another coding agent in your product's repo, install Remocn, and ask for one flow of your product. The agent reads your codebase for the product name, copy and flow, rebuilds the screens as scripted React components in a Remotion project, and renders a ~50-second MP4 that stays editable as code.

Remocn is what the agent builds with: an [agent skill](/docs/getting-started/agent-skill) for any agent that loads Agent Skills, a [plugin](/docs/getting-started/plugin) for Claude Code and Codex with a `/remocn:video` workflow, and a shadcn-style registry of MIT-licensed Remotion components (app screens, UI primitives, cursors, transitions, text) that it installs with `npx shadcn@latest add @remocn/<name>`. It is free and open source, with no account and no hosted service.

## How do I make a product demo video with an AI coding agent?

1. **Install the Remocn plugin.** In Claude Code:

   ```text
   /plugin install remocn --marketplace Remocn/remocn
   ```

   In Codex:

   ```bash
   codex plugin marketplace add Remocn/remocn
   codex plugin add remocn@remocn
   ```

   Another agent: install the skill instead, then ask the agent to set up Remotion ([Setup](/docs/guides/setup) has the prompt).

   ```bash
   npx skills add Remocn/remocn --skill remocn --yes
   ```

2. **Ask for the demo in one line,** from your product's repo. Name the product and the one flow to show:

   ```text
   /remocn:video 50-second product demo for Tasklane: a user pastes a link, a preview builds itself, the share button lights up
   ```

   The agent reads your `README`, landing copy, `package.json` and recent releases, then shows a storyboard and waits for your go-ahead before writing code. If the repo has no Remotion project, it creates one in a new folder. For more control, paste the full prompt from [The prompt](#the-prompt) instead.

3. **Preview it.** Open the project in [Remocn Studio](https://remocn.studio) (the plugin offers this when the video is built), or run:

   ```bash
   npx remotion studio
   ```

   Then direct it in plain sentences, one change at a time. See [Directing the result](#directing-the-result).

4. **Render the MP4.** Ask the agent to "Render the video.", or run the render yourself. Each video is registered as a composition with id `<slug>`:

   ```bash
   npx remotion render <slug> out/<slug>.mp4
   ```

## From your codebase

What the agent takes from your repo, and what it doesn't:

- **Your words.** The [video workflow](/docs/getting-started/plugin) pulls the product name, copy and recent releases from your `README`, landing copy and `package.json`, and asks only for what is still missing.
- **Your design tokens.** Remocn's UI primitives ([remocn-ui](/docs/ui)) use stock shadcn/ui token names: `primary`, `background`, `border`, `radius` and the rest. If your app uses shadcn/ui, ask the agent to copy the values from your `globals.css` into the video's theme. Animated colors need concrete values (oklch, hex or rgb), not `var(--primary)`; [Theming](/docs/ui/concepts#theming) explains why. For everything else, the [brand brief](/docs/guides/your-brand) keeps your colors, font and logo in one file the agent reuses.
- **Your screens.** The agent rebuilds your UI from Remocn's UI primitives and app-screen components rather than running your app, because a video frame has to render the same way every time: no data fetching, no hover state, no clock. Give it a screenshot when it needs to look closer to your app.
- **Where the video lives.** Every component is copied into your project as source, so the video is ordinary React and TypeScript that sits next to your code and goes through git like the rest of it.

## Which approach fits

There are four common ways to get a product demo video out of your code. Facts about RepoClip and agentic-product-demo come from their own pages, checked on November 10, 2026; the Playwright row describes the general approach.

| | How the video is made | What it reads | What you can edit afterwards | Cost and setup | Fits when |
|---|---|---|---|---|---|
| [RepoClip](https://repoclip.io/product-demo-video-maker) | Hosted service. AI writes a script and generates the visuals and narration for each scene | A public or private GitHub repo URL | The video, through the service | Account required. One free video a month, paid plans above that | You want a narrated explainer from a repo URL with nothing to install |
| Playwright-based recording skills (a general pattern, not one tool) | The agent drives your running app in a headless browser and records the screen | Your running app | The recording script, then the footage | Your app running locally with demo data | You need the real pixels of your app, and a screen recording look is fine |
| [agentic-product-demo](https://github.com/Alexwtlf/agentic-product-demo) | A Claude Code skill and a motion kit. The agent draws your app in React and renders it with Remotion | Your repo, running app or site, and your stylesheet's tokens | The composition, as code | MIT kit, Node 20+, Remotion | You want a short UI clip in your app's own styling, built from one kit |
| Remocn | A skill, plugin and component registry. The agent composes a full storyboard from installed Remotion components and renders it locally | Your repo's `README`, landing copy, `package.json` and releases | Every component, as source in your project | Free and MIT, no account. Remotion project required | You want a complete demo (setup line, flow, payoff, install command) and will make more videos from the same parts |

Remotion has its own license: free for individuals and small companies, with a paid company license for larger teams. Both Remotion-based options above inherit it. Check [Remotion's license](https://www.remotion.dev/license) for the current thresholds.

## What the demo is

This is the video where your product does the talking. A recreated app screen acts out your core flow — something is clicked, the UI responds, the result lands — pixel-perfect and scripted, so it looks cleaner than a screen recording. No cursor hunting for a button, no loading spinners, no stray notifications. In the [Feature announcement](/docs/guides/feature-announcement) this is one beat called the demo; here that beat grows into the whole video.

<GuideBeatList>

1. **The setup** — One line naming who this is for and the job to be done.
2. **The screen appears** — Your app UI slides in, calm, no action yet. Let the viewer see where they are.
3. **Step one** — The flow begins: something is clicked or typed, the UI responds.
4. **Step two** — The next step of the same flow, given room to be seen.
5. **Step three** — The last step; the flow completes on camera.
6. **The payoff** — The outcome on screen, plus one line saying what just happened in the user's terms.
7. **The close** — A terminal types your install command or URL, then your logo.

</GuideBeatList>

The three flow steps are most of the runtime. Everything else frames them.

## Your words<GuideCount n={7} />

<GuideWords
  examples={[

    { blank: ["<PAYOFF LINE>"] },
    { blank: ["<INSTALL COMMAND OR URL>"] },
    { blank: ["<CLOSING LINE>"] },
    { color: "#D4F25C", note: "Leave empty for the default lime" },
  ]}
>

- **Product name**
- **Setup line** — Who this is for and the job, one sentence
- **The one flow** — Told as three steps, each a short sentence describing what happens on screen ("the user pastes a link", "a preview builds itself", "the share button lights up")
- **Payoff line** — What the user just got, in their words
- **Install command or URL** — One, not both
- **Closing line**
- **Accent color** _optional_ — One hex value; the default lime looks good

</GuideWords>

Pick one flow. A demo that shows three features demos none — the viewer should finish the video able to retell the flow from memory. If your product has three flows worth showing, that's three videos.

## The prompt

Paste it into your agent with your words in place of the highlighted blanks.

<GuidePrompt>

```text
I'm making a product demo video with remocn (remocn.dev).

Build a ~50-second, 1920×1080, 30fps demo video for <PRODUCT NAME> in this
Remotion project, using remocn components — install anything you need with
`npx shadcn@latest add @remocn/<name>`:

1. Setup — one calm line: "<SETUP LINE>".
2. The screen — a recreated app screen for <PRODUCT NAME> slides in and
   settles. No action yet — just the interface at rest.
3. Step one — <FLOW STEP 1>. Show the interaction and the UI responding.
4. Step two — <FLOW STEP 2>. Same screen, the flow continuing.
5. Step three — <FLOW STEP 3>. The flow completes on camera.
6. Payoff — the outcome stays on screen while one line lands:
   "<PAYOFF LINE>".
7. Close — a terminal line that types itself: `<INSTALL COMMAND OR URL>`,
   then my logo (<LOGO FILE, or: use the product name as a wordmark>) with
   a closing line: "<CLOSING LINE>".

The app screen is the star: recreate a clean, believable version of my UI
and script every interaction — deliberate clicks, typing that a viewer can
follow, responses that land with a beat of rest. Give the three flow steps
the most screen time. Style: warm dark background (#141318), off-white
text, one accent color <ACCENT COLOR>, Manrope. Keep transitions restrained
— the screen holds still, the flow moves. Use my copy exactly as written.
```

</GuidePrompt>
